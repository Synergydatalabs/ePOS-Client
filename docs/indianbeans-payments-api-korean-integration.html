Indian Beans Payments API — Korean Integration Guide

Accept KakaoPay / card payments on your Korean site in three steps · API host: https://indianbeans.com

Overview

Your server generates a payment on indianbeans.com → we return a hosted checkout URL, a QR code and an iframe URL. The customer pays via KakaoPay inside an iframe embedded on your site. On completion, your browser receives a postMessage and your server receives a webhook. Everything is driven by your API key — your customers never leave your site.

Prerequisites

  1. An Indian Beans account at https://indianbeans.com/signup.
  2. An API key: Portal → Settings → API Keys → Create new key. Copy it immediately — the full value is shown once.
  3. A webhook endpoint on your server (optional but recommended) that we can POST to on payment success / failure.

Step 1 · Create a payment (your server)

From your backend, call this endpoint for every new order. The response includes everything your frontend needs.

curl -X POST https://indianbeans.com/api/public/v1/payments \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 3000,
    "currency": "KRW",
    "payment_methods": ["kakao_pay"],
    "qr": true,
    "customer": {
      "email": "buyer@korean-site.co.kr",
      "name": "홍길동"
    },
    "description": "Order #YOUR_ORDER_ID",
    "webhook_url": "https://your-site.co.kr/webhooks/hub-paid",
    "metadata": { "order_id": "YOUR_ORDER_ID" }
  }'

Response (201 Created):

{
  "id":           "cmg...",
  "status":       "created",
  "amount":       3000,
  "currency":     "krw",
  "checkout_url": "https://indianbeans.com/l/AbCdEfGh",
  "embed_url":    "https://indianbeans.com/l/AbCdEfGh?embed=1",
  "qr_data_url":  "data:image/png;base64,iVBORw0KGgoAA...",
  "link_slug":    "AbCdEfGh",
  "payment_methods": ["kakao_pay"],
  "created_at":   "2026-10-09T12:34:56Z"
}

Step 2 · Embed on your customer-facing page

Drop this where you want the payment widget. Replace EMBED_URL with the embed_url from Step 1.

<iframe
  id="hub-payment"
  src="EMBED_URL"
  width="100%"
  height="700"
  frameborder="0"
  allow="payment"
  style="border:0; max-width:480px; display:block; margin:0 auto;"
></iframe>

<script>
  window.addEventListener('message', function(e) {
    if (e.origin !== 'https://indianbeans.com') return;   // always verify origin
    if (e.data && e.data.type === 'payment:succeeded') {
      // Payment confirmed on our side. Example reactions:
      document.getElementById('hub-payment').style.display = 'none';
      document.getElementById('thank-you').style.display = 'block';
      // Optional: double-check with your backend
      fetch('/mark-paid?invoice=' + encodeURIComponent(e.data.invoiceId));
    }
  });
</script>

Step 3 · Receive the webhook on your server

On payment success or failure we POST your webhook_url with a JSON body. Verify, mark the order paid, respond 200 OK.

POST https://your-site.co.kr/webhooks/hub-paid
Content-Type: application/json

{
  "event": "payment.succeeded",
  "payment": {
    "id":       "cmg...",
    "amount":   3000,
    "currency": "krw",
    "status":   "paid",
    "method":   "kakao_pay"
  },
  "customer": { "email": "buyer@korean-site.co.kr", "name": "홍길동" },
  "metadata": { "order_id": "YOUR_ORDER_ID" }
}
Why both postMessage + webhook? The postMessage is instant UI feedback for the customer in the iframe. The webhook is the authoritative server-to-server confirmation — trust it, not the client. Always mark orders paid from the webhook, not the browser.

Reference

Request fields (POST /api/public/v1/payments)

FieldTypeNotes
amountintegerSmallest unit (₩ for KRW, cents for USD). Required.
currencystringISO 4217 code. KRW, USD, CAD, EUR, etc.
payment_methodsstring[]["kakao_pay"], ["paypal"], ["alipay"] — or omit for Stripe card.
qrbooleantrue to receive qr_data_url in the response.
customer.emailstringRequired. Shown on receipt + email target.
customer.namestringOptional. Supports Korean characters.
descriptionstringShown on the checkout page. ≤ 500 chars.
webhook_urlstringWhere we POST on payment events. HTTPS.
metadataobjectAny JSON. Echoed in the webhook payload.

postMessage event (from iframe → your parent window)

{
  "type":          "payment:succeeded",
  "invoiceId":     "cmg...",
  "invoiceNumber": "INV-2026-0042",
  "amountCents":   3000,
  "currency":      "KRW"
}

Response URLs

URLUse for
checkout_urlFull-page checkout. Send via email, SMS, or redirect.
embed_urliframe source. Chrome stripped, postMessage on paid.
qr_data_urlInline PNG QR of checkout_url. Scan with KakaoPay app.

Testing checklist

  • POST the request from your server. Response must be 201 and include embed_url.
  • Open checkout_url in a browser — Indian Beans checkout loads with your amount.
  • Open embed_url in a browser — same page, header + footer stripped.
  • Scan qr_data_url with any QR reader — resolves to checkout_url.
  • Complete a test payment with a real Korean phone + KakaoPay app (small amount, refund via Paddle dashboard after).
  • Confirm your webhook endpoint received the payment.succeeded POST.
  • Confirm your parent-page message listener fired with type: 'payment:succeeded'.
Security: never ship your API key in frontend code. Always call the /payments endpoint from your backend. The iframe URL is safe to expose — it's a short-lived single-use session.
